# MeetNameSentry

Google Meet 参会者命名巡检 Chrome 扩展，支持关键词规则、白名单和自动移出不合规成员。

> **v1.0.1 复审构建说明（2026-10-14）**：本包保留原来的姓名关键词规则及版本号 `1.0.1`，但修复了设置窗口关闭导致试运行开关未保存、头像缩写误认姓名、隐藏文本和 `ghost` 主持人误判、滚动扫描绕过安全熔断的问题。完整复核记录与未覆盖的真实 Meet 风险见 [AUDIT.md](AUDIT.md)。旧版累计模拟测试 83/83 通过；最新安全审核累计 91/91 通过，尚未做真实会议自动移出端到端测试。

## 功能

- **关键词检查**：拉丁字母/数字必需标记须为姓名的前缀或后缀，不能嵌入英文词或夹在姓名中间，而且不能只有标记、没有实际姓名。中文必需关键词沿用原有包含语义。支持大小写与全半角规范化。
- **双重白名单**：支持关键词白名单及完整姓名白名单。
- **自动打开名单**：巡检运行时，如果没有可见参与者名单，会尝试打开参与者面板；聊天面板打开也可切换。
- **试运行**：只提示不合规成员，不执行移出。
- **执行保护**：目标需经过两次稳定判定；移出过程中复核目标，配置改变或用户接管时中止旧操作；候选按钮不明确时停止猜测。
- **恢复巡检**：面板打开失败会退避重试，名单恢复后重新绑定监听。

## 安装

本项目以解压后的 Chrome 扩展形式使用。

1. 从 [Releases](https://github.com/hubg9527777-dotcom/MeetNameSentry/releases) 下载新版扩展压缩包，并解压到一个固定目录。也可以下载或克隆本仓库。
2. 在 Chrome 地址栏打开 `chrome://extensions/`。
3. 开启右上角的“开发者模式”。
4. 点击“加载已解压的扩展程序”，选择包含 `manifest.json` 的目录。
5. 将扩展固定到工具栏，方便配置。
6. 刷新已经打开的 Google Meet 页面。

更新时替换扩展文件，在扩展管理页面点击“重新加载”，再刷新 Meet 页面。仅替换文件不会更新已运行标签页中的脚本。

## 默认行为

| 设置 | 首次默认值 |
|---|---|
| 启用巡检 | 开启 |
| 试运行 | **关闭** |
| 必需关键词 | `AA` |
| 关键词白名单 | 空 |
| 姓名白名单 | 空 |

**首次安装默认会实际移出不符合 `AA` 规则的成员，前提是当前账号有移出权限。请在进入正式会议前打开设置，配置自己的规则。** 已保存的设置优先于默认值，更新不会强制覆盖已有选择。

## 配置与使用

点击工具栏中的 MeetNameSentry 图标打开设置。更改会自动保存，请确认出现“已保存”；保存失败时原设置可能仍然生效。

| 设置项 | 说明 |
|---|---|
| 启用巡检 | 关闭后停止扫描及自动点击。开启后可自动切换到参与者面板。 |
| 试运行 | 开启后仍读取名单，但不真正移出成员。建议先用于检查规则。 |
| 名字必须包含 | 多个关键词用逗号、顿号、分号或换行分隔，任意一个符合即通过；AA 等拉丁标记只能作为姓名前缀或后缀，必须另有姓名文字；中文关键词维持包含匹配。留空不执行移出。 |
| 关键词白名单 | 姓名命中白名单关键词，即不受必需关键词限制；英文缩写同样按完整标记匹配，防止英文词尾误放行。 |
| 姓名白名单 | 每行一个完整姓名，按规范化后的完整姓名匹配。 |
| 额外的“移出”菜单文案 | 界面语言未覆盖时填写完整菜单文字；使用完整匹配，不填写泛化词语。 |

示例：

```text
名字必须包含：AA，BB
关键词白名单：助教，TA
姓名白名单：
张三
李四
```

在此配置下，`AA-王五`、`BB-赵六`、`助教-陈老师`、`张三`都通过检查；没有命中规则或白名单的其他成员会被标记为不合规。

### v1.0.1 更新版复核：前缀 / 后缀姓名标记与 Unicode 假边界

设置“名字必须包含：AA”时，默认判定如下：

| 放行 | 不放行 |
|---|---|
| `AA张三`、`王五AA` | `jdka laa`、`laa` |
| `AA 张三`、`张三 AA` | `BAA`、`AAlice`、`AliceAA` |
| `AA-张三`、`张三-AA` | `AA123`、`123AA` |
| `[AA]张三`、`张三(AA)` | `张AA三`、`张三 AA 李四` |
| `AA-John`、`John-AA` | `AA`、`AA---`、`AA 12345` |

**严格定义**：AA 必须为完整拉丁标记，且它之前不能有姓名文字（前缀），或之后不能有姓名文字（后缀）；另外必须有至少一个字母作为实际姓名。前后可有空格、括号、横线或装饰符，但不接受把 AA 偷放在两个姓名片段之间。

姓名匹配会去除 Unicode 默认不可见字符（例如 U+2063）后再检查边界，避免 `AA<不可见字符>lice` 看起来像 `AAlice` 却被误放行。全角英文字母仍按旧设置转换成普通字母。`关键词白名单` 仍执行独立完整标记匹配，`姓名白名单` 仍执行完整姓名匹配；两类白名单都可能绕过必需关键词规则，须谨慎设置。

**另外两项防绕过**：昵称中自行填写 `(You)` 或 `(presentation)` 不再足以获得自己/演示流豁免；优先读取实际显示的昵称而不是包含附加说明的 aria-label。如果 DOM 信息无法确认一致，该行将被跳过，避免错误移出。

**兼容性提醒**：这一更新版沿用最新的严格规则，较早期的同版本构建更严格。此前被允许的 `张AA三` 或 `AA` 将被判为不合规；旧配置保留，包括已经关闭试运行的设置，升级后可能立即影响在线参会者。正式使用前请先主动开启“试运行”。

建议升级后先开启“试运行”检查实际参会名单，确认合规识别后再启用真正移出。升级不会清除已有配置。

执行移出需要 Google Meet 主持人或联席主持人的相应权限。插件不能绕过 Meet 自身的权限控制。

## 无痕模式与访客参会者（显示姓名准入）

**不要求员工使用固定 Google Meet 账号、邮箱、登录状态或跨会议稳定的 participant-id。** 即使员工通过无痕模式或访客模式进入会议，只要 Meet 参与者面板能可靠显示昵称，就执行同一套 `AA` 命名规则及已配置的姓名白名单。浏览器扩展安装在执行巡检的主持人浏览器中，员工无需安装插件。

- 姓名合规判定取决于 Meet 当前显示的昵称，**不依赖账号 ID**；浏览器会话变化不会改变 AA 字符串规则。
- Meet 偶尔提供的 `data-participant-id` 只在当次页面里辅助定位按钮、避免点错人；不存在时退化为规范化姓名。不会保存为跨会议员工名单，也不拿 ID 决定是否放行。
- **两个未提供 ID 且显示姓名完全相同的参会者**，目前插件不猜测应该点谁的操作按钮，会跳过这次自动移出以防误点。两人的姓名合规结果相同，但无法保证 DOM 操作目标唯一。这是当前安全限制，不是额外要求员工登录。
- 当前保留原有的本人、主持人/联席主持人和演示流豁免（由页面提供的身份信号触发）；这些不是员工身份认证体系。若需取消这些豁免，应作为单独业务规则变更讨论。
- 确认弹框不一定提供目标昵称；目前不能仅通过“名字准入”推导自动确认绝对安全，仍需现场检查 UI 的定位准确性。

## 状态与排查

页面左上角显示巡检状态。

- **等待输入结束**：停止输入约3秒后会继续尝试切换面板，输入框保有焦点不会永久阻止巡检。
- **未识别到唯一的参与者按钮**：页面布局或语言可能不匹配，插件持续重新识别；请检查是否已更新扩展并刷新页面。
- **等待可见名单**：参与者面板已展开，但名单尚未被识别或渲染。
- **面板打开失败**：多次失败后等待30秒再试；手动打开名单可恢复面板巡检。
- **已暂停**：检查启用开关或显示的暂停原因。移出失败引发的安全暂停不会因为手动打开名单而解除。
- **不执行移出**：检查试运行、必需关键词、白名单及主持人权限；只有确认目标不合规且按钮可可靠识别时才执行。

提交问题时，请提供界面语言、具体状态、复现步骤和已遮盖个人信息的截图。不要提交密钥、完整会议链接或不必要的参会者名单。

## 隐私与权限

- 扩展仅声明 `storage` 权限，通过静态内容脚本运行于 `https://meet.google.com/*`。
- 没有额外 `host_permissions`，没有远程脚本或应用自己的网络上传逻辑。
- 设置和姓名白名单保存在 `chrome.storage.sync`；开启 Chrome 同步时，可能同步到同一账号的其他浏览器。
- 常规控制台日志不记录完整参会姓名；页面状态提示仍可能显示截断姓名，屏幕共享时请考虑可见范围。

## 使用限制

- 本工具检查**显示姓名**，不能替代身份验证或 Meet 正式入会审批；包含关键词或白名单姓名不证明实际身份。
- 本人仅在可用的参与者 ID 明确匹配时才自动豁免；主持人和演示流仍依赖页面的次级标签，存在识别不准或遗漏风险。当前无法确认页面信息的行会保守跳过，可能漏检。
- 当前确认框没有启用强制姓名校验；已有目标复核保护不能完全排除界面变化造成的误绑定。
- Google Meet 的页面结构可能变化，不保证所有语言、布局及大型虚拟列表都兼容。
- 确认框关闭被作为成功信号，实际移出结果仍应在会议名单中核实。

建议先在测试会议开启试运行验证规则和界面兼容性，再使用实际移出功能。

### 尚未消除的风险（本地测试不能替代真实 Meet 验证）

1. **显示名不等于身份**：任何参会者都可能主动将昵称改成 `AA张三`。仅靠文本标记无法核对其真实姓名和授权。
2. **名单解析可能失败**：Meet 的不同语言、布局、重复姓名、虚拟滚动列表、元数据标记都可能造成漏检；可见昵称与无障碍标签冲突时会跳过而不误移出。
3. **移出确认目标未做强制姓名绑定**：菜单和确认框都是页面界面元素，改版、复用或模态框出现时虽有复核保护，仍有误点风险；当前 `STRICT_DIALOG_NAME_CHECK` 保持 `false`，因为没有真实会议样本确认每个语言均显示受邀者姓名。
4. **首次安装默认为实际移出**：`dryRun=false` 沿用旧版默认值以兼容旧配置，不是最保守的部署选择。请人工打开“试运行”并看到“已保存”后再测试。
5. **结果确认属于尽力而为**：确认对话框关闭只证明交互已完成，并不能独立证明对方确实离开会议。
